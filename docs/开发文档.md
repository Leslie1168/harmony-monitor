# 开发文档

面向第一次接手这个项目的开发者。读完后应该能改代码、跑测试、打包发布。
（用户视角的操作说明在 [使用说明.md](使用说明.md)。）

## 一、项目是什么

Windows 桌面无边框悬浮窗，通过**无线方式**实时监控多台鸿蒙设备的运行状态
（CPU / 内存 / 存储 / 电量 / 温度 / Wi-Fi 等），监控项可勾选，最快 1 秒刷新。

界面（v5 起）全部由 HTML/CSS/JS 编写，用 QtWebEngine（Chromium）渲染；
Python 只负责窗口、托盘、采集和数据推送。早期 Qt 手绘版的思路仍留在 `app/overlay.py`
的双渲染路径判断里，可作为回退参考。

## 二、代码在哪

| 内容 | 位置 |
|---|---|
| 源码 | `app/*.py` + `app/webui.html` + `main.py` |
| 虚拟环境 | `.venv/Scripts/python.exe`（Python 3.12 + PySide6 6.12） |
| 从源码直接跑 | `.venv/Scripts/python.exe main.py` |
| 打包产物 | `dist/HarmonyMonitor/` |
| 运行日志 | 程序目录 `monitor.log`（未捕获异常）、`worker.log`（采集与重连，2 MiB 轮转） |

### 源码文件职责

| 文件 | 职责 |
|---|---|
| `main.py` | 入口：配置原子保存（临时文件 + `os.replace`）、单实例（`QLockFile` + IPC）、异步停止采集线程、托盘 |
| `app/overlay.py` | **薄窗口层**：QWebEngineView + QWebChannel 桥；`appearance()` 配置校验、`MINI_REQUIRED`、状态推送（60 ms 节流）、离线保数值 `_sticky` |
| `app/webui.html` | **全部 UI**：玻璃卡片、三圆环、模式菜单、双击改名、悬停详情条、呼吸 / 充电光圈 / 离线变灰动画 |
| `app/collectors.py` | 指标定义（`ITEMS` 29 项）+ hdc 命令与解析 |
| `app/adb_collectors.py` | adb 后端命令与解析（鸿蒙 4.x） |
| `app/hdc_client.py` | `HdcClient` / `AdbClient` 进程封装，支持 `stop_event` 取消子进程，ADB 服务启动加锁 |
| `app/worker.py` | `DeviceWorker(QThread)`，分档轮询、持续重连、分档失败隔离、日志 2 MiB 轮转 |
| `app/settings_dialog.py` | Qt 设置对话框（设备 / 监控项 / 外观）——**未迁移到 Web**，与网页 UI 并存 |

## 三、架构与数据流（v5 关键变化）

```
DeviceWorker(QThread) ──updated/status 信号──▶ OverlayWindow
   │                                           │ 缓存 _data_cache/_status_cache
   │                                           │ 60ms 合并节流
   │                                           ▼
   │                                  page.runJavaScript("__applyState(json)")
   ▼                                           ▼
hdc/adb 子进程                          webui.html 全量重渲染或增量 patch
                                                │
   JS ──QWebChannel──▶ _Bridge 槽 ──▶ Python：
        setMode / switchDevice / renameDevice / togglePin /
        openSettings / minimize / quitApp / startMove / reportSize
```

- 窗口尺寸由 JS 量完内容后 `reportSize(w, h)` 上报，Python `setFixedSize`
- 拖动：JS 在空白处 mousedown → `bridge.startMove()` → Qt 原生 `startSystemMove()`
- **离线保数值**：worker 断线会发清空帧（全 None），overlay 的 `_sticky`
  缓存 cpu/mem/battery 最后非 None 值，推送时回填

## 四、设备连接

| 通道 | 系统 | 地址形态 |
|---|---|---|
| hdc | OpenHarmony 7 / API 26 | `IP:43891`（无线调试页给的端口） |
| adb | HarmonyOS 4.2 / API 12 | `IP:5555` |

- 4.x 设备无「无线调试」开关，只能插 USB 跑 `开启无线调试.bat`（`adb tcpip 5555`）
- **4.x 设备重启后无线失效**，必须重新插线跑一次 bat
- 工具链：`hdc/hdc.exe`（鸿蒙）、`tools/adb/adb.exe`（4.x），打包时与源码目录各留一份
- 不要动设备端设置、不要改 USB 驱动（会破坏多屏协同等其他功能）

## 五、四种显示模式与交互

| 模式 | 内容 | 去别处的方式 |
|---|---|---|
| 完整 full | 多台卡片并排 | 顶部分段切换 |
| 标签 tabs | 单卡片 + 设备标签页（**程序默认打开**） | 分段切换 / 右上「扩展 ⤢」→ full |
| 迷你 mini | 350×190 玻璃卡：自定义名称标签 + 三圆环 | 右上「⇄」弹四项模式菜单 /「⤢」→ mini3 |
| 三台并排 mini3 | 多张迷你卡片 + 顶栏 | 顶栏分段切换 /「收起 ⤡」→ mini |

迷你模式专属：

- **双击标签改名**（≤6 字，存 `appearance.mini_labels`，重启保留；Esc 取消）
- **📌 固定**：窗口始终置顶，绿色高亮；状态存 `appearance.topmost`，与设置对话框同步
- **悬停详情条**：温度 / Wi-Fi / 存储 / 运行时长（离线时显示状态与地址）
- 状态表现：超标环变色（CPU ≥70 黄 ≥90 红；内存 ≥70 黄 ≥85 红；电量 ≤35 黄 ≤20 红），
  只有红档环呼吸；充电时电量环外圈流动光点；离线整卡变灰但保留最后一次数值

## 六、配置文件 config.json

```json
{
  "devices": [{"addr": "192.168.1.23:5555", "type": "adb"}],
  "selected": ["cpu", "mem_pct"],
  "window": {"x": 122, "y": 259},
  "appearance": {
    "mode": "tabs",
    "tab_device": "192.168.1.23:5555",
    "topmost": true,
    "opacity": 92,
    "card_width": 330,
    "scale": 100,
    "font": "Microsoft YaHei UI",
    "mini_labels": {"192.168.1.23:5555": "手机"}
  }
}
```

- 保存是**原子的**（临时文件 + fsync + `os.replace`），写失败不动原文件
- 读取时逐字段容错：损坏的 `devices` / `selected` / `window` / `appearance` 各自回退默认，未知字段保留

## 七、采集档位

| 档位 | 间隔 | 覆盖指标 |
|---|---|---|
| fast | 1 秒 | CPU、负载、内存、存储、进程数 |
| mid | 5 秒 | 电池、Wi-Fi、IP |
| slow | 30 秒 | 运行时长、CPU 温度、屏幕亮度 |

特例：**迷你 / mini3 模式强制附带** `MINI_REQUIRED`（cpu、mem_pct、battery、batt_state、
batt_temp、wifi_rssi、storage_pct、uptime）——悬停详情条需要 mid/slow 档数据，
所以迷你模式流量比只看三环大，这是设计决定不是 bug。

`worker._command()` 还会按勾选裁剪命令里的重活：没勾进程数就把 `ps | wc -l` 换成 `:`，
没勾存储就把 `df -h /data` 去掉，没勾负载就不执行 `nproc`。

## 八、关键坑（改代码前必读）

1. **`hidumper` 服务正文只在 TTY 输出**，接管道就丢——所有 hidumper 查询必须全量取回 Python 端解析
2. 内存必须用 `MemTotal − MemAvailable`，`free` 的 used 虚高 97%
3. load 是绝对值要除核数，文字可超 100%
4. 鸿蒙 4.x 的 `hidumper` / sysfs 被 SELinux 限制，用 `dumpsys`
5. 市场名属性是 `ro.config.marketing_name`，不是 `marketname`
6. **WebEngine 冻结路径**：打包后 `__file__` 在 `_internal/app/`，而 `webui.html` 打到
   `_internal/` 根——`overlay.py` 的 `WEBUI_PATH` 已做 `sys._MEIPASS` 感知，别改回 `__file__` 拼接
7. **打包前必须杀 `hdc.exe`**（`hdc kill` + `taskkill`），否则 dist 目录被锁删不掉
8. `QThread.wait()` 单位是**毫秒**（PySide6），`wait(5)` 只等 5 ms
9. worker 用 `stop_event` 取消子进程；UI 线程**禁止** `wait()`，停止必须走 finished 信号异步收尾
10. 转 ICO 的图若是"白底 + 圆角方块"，必须裁边 + 圆角外做透明（用 Pillow），否则图标四角有白边
11. 桌面快捷方式用 **pylnk3**（或 `make_shortcut.py` 直接按 MS-SHLLINK 规范写）生成，
    比 COM 调用可靠
12. WebEngine 让包体 ~570 M、冷启动慢 1~2 秒——这是换取玻璃质感界面的既定代价，别试图"优化"回 Qt 手绘

## 十一、打包与发布

```bat
rem 1. 停进程（hdc 常驻会锁目录）
hdc\hdc.exe kill && taskkill /F /IM hdc.exe && taskkill /F /IM adb.exe
taskkill /IM HarmonyMonitor.exe

rem 2. 打包
.venv/Scripts/pyinstaller.exe --noconfirm --windowed --onedir --name HarmonyMonitor ^
  --distpath dist --workpath build --specpath build ^
  --icon app_harmony.ico ^
  --add-data "app_harmony.ico;." --add-data "app/webui.html;." ^
  --exclude-module tkinter --exclude-module PIL --exclude-module numpy main.py

rem 3. 布置运行时
mkdir dist\HarmonyMonitor\hdc  dist\HarmonyMonitor\tools\adb
copy hdc\hdc.exe hdc\libusb_shared.dll  dist\HarmonyMonitor\hdc\
copy tools\adb\*.exe tools\adb\*.dll    dist\HarmonyMonitor\tools\adb\
copy config.json app_harmony.ico 开启无线调试.bat  dist\HarmonyMonitor\

rem 4. 需要的话用 make_shortcut.py 生成桌面快捷方式
rem 5. 换图标：Pillow 把方图转多尺寸 ICO 覆盖 app_harmony.ico → 重打包 → ie4uinit.exe -show
```

> `--add-data` 用绝对路径更稳，相对路径会相对 spec 目录解析。
